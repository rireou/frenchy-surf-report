# Local verification

Validated in the desktop Chromium browser after starting the foreground PowerShell launcher in the owner's normal Windows session. The earlier background launcher printed URLs despite an `EADDRINUSE` failure. That process was stopped; the replacement keeps Node in the foreground, shows errors and prints READY only after both routes return 200. The server's `/health` endpoint reports its PID, port and `productionWrites:false`.

- Research memory: search/type filters, original provenance expansion, prior experiments, zero-prospective state, disabled archive status and collection priorities.
- Historical PR72 dashboard: version/time/source filters, nine condition views, B/C/D comparisons, regressions, audit search and keyboard-opened record details. Original analytical results are reused.
- Observation form: confirmed and corrected synthetic saves, separate typical/set values, optional confidence/quality/local factors, remembered explicit size conventions, measured-field reset on a new time, history after reload and JSON export. The two exported fixture records retain explicit validation status, original model snapshots and matching observation timestamps.
- Responsive checks: 1440, 768, 390, 360 and 320 CSS-pixel viewports, verifying the actual tab's `innerWidth` and document scroll width. No page-level horizontal overflow after fixes. The mobile save target exceeds 44 px. Scrollable comparison tables remain local to their containers.
- Browser-discovered fixes: malformed type options, long-text/filter overflow, an inherited historical-footer hash overflow, observation CSS depending on the public shell's box-sizing reset, and interacting with filters before private data finished loading. These affect private research/observation presentation only.
- Console: no new errors/warnings in final tested pages after fixes. No production API calls or writes are part of this local preview.
- Actual loopback HTTP checks: both pages 200; private file/source paths 404; POST 405; foreign Origin and a real foreign Host header 403; no-store/noindex/nosniff. The default local preview is owner-only and read-only, not an authenticated hosted environment.
- Automated coverage: existing Node/Python tests plus immutable history, evidence/model tampering, actual SDK conditional request headers, authenticated hosted handler/CSRF rejection, archive seals/timing/staleness, disabled/preview guards, 168-hour archive parity, typical/set targets, version grouping, larger-surf undercalls and day/event sensitivity. Function bundles and inline scripts compile. Private JS/Python inference parity is checked separately against the frozen private artifact.

Native Samsung/Android hardware and a live Netlify scheduled run are **not** certified by desktop viewport tests. Hosted authentication is exercised through the actual handler with synthetic stores/sessions; its deployed HTTPS behaviour must be verified after owner approval. The collector remains disabled and no prospective accuracy improvement is claimed. Private screenshots, exports, fitted artifacts and populated dashboards stay outside public Git and deployment assets.
